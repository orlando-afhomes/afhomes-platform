# 01 · Localhost

[Roadmap](../README.md) · Previous: [Documentation alignment](../00-update-existing-documentation.md) · Next environment: [Staging](../02-staging/README.md)

Build and test on your computer with Firebase emulators and synthetic records. Keep the current browser-memory prototype available for the early demo while the real API is being built.

## Work in order

| Step | Guide | Finish before advancing |
| --- | --- | --- |
| 01 | [Database and emulators](01-database-and-emulators.md) | The local schema and fake data can be recreated. |
| 02 | [Backend, authentication, and permissions](02-backend-authentication-and-permissions.md) | Staff identity resolves to approved application permissions. |
| 03 | [API](03-api.md) | Endpoints enforce validation, record access, and atomic approval. |
| 04 | [Frontend and file storage](04-frontend-and-file-storage.md) | The first workflow works in the existing screens. |
| 05 | [Approved business modules](05-approved-business-modules.md) | Every approved module has an implemented and tested local workflow. |
| 06 | [Local verification](06-local-verification.md) | The evidence is ready for complete staging rehearsal. |

Obtain owner authorization for the local backend/database foundation and for each module before implementation. After Step 04 passes the pilot checks, take the first workflow to [staging SQL Connect](../02-staging/01-firebase-project-and-database-trial.md). Prove its hosted transaction behavior before expanding financial workflows. Continue the remaining local modules against the same approved rules and typed contracts.
