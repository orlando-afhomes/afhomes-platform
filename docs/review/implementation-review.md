### IR-66D760B6D78ED62E — Saving a staff profile breaks its private avatar

- Category — Data integrity
- Severity — High
- Status — Resolved
- Description — Uploading an avatar writes its private file reference, then the ordinary profile save replaces that reference with a profile that contains only the URL.
- Evidence — Both edit forms upload first and then update the staff profile. The upload stores avatarFile in the profile JSON. The staff update rebuilds the JSON from whitelisted fields plus avatarUrl. The download requires avatarFile, and removal tries to find it after the overwrite.
- Cause — Two writes own the same JSON object. The ordinary staff update omits the server-owned avatar metadata and runs removal after replacing the object.
- Impact — A successful save or later ordinary edit can leave a broken photo URL and a private file that no longer has a record reference. Removing an avatar can also leave its storage object behind.
- Recommendation — Preserve the server-owned metadata across profile edits. Capture the old metadata before clearing the reference and make replacement safe against concurrent writes. Add an integrated upload, save, reload, replace and remove check.

### IR-DA190CB990D49193 — Member creation grants sales roles without account authorization

- Category — Authorization
- Severity — High
- Status — Resolved
- Description — A sales leader can reach the member creation service, which can activate a sales role on the account named in the request.
- Evidence — The member API accepts an optional account ID. The network manager guard admits SVD, SSM and SM. The new role upsert runs under that guard alone. Business rule 01 §§3.3 and 3.7 restricts role delegation and makes sellers view-only.
- Cause — The network record permission is reused for a separate account access change. The ordinary account-role service performs target and role checks that member creation omits.

- Recommendation — Require authorized office role delegation and validate the account link before writing the member and role together. Apply the same authorization to designation changes that update account roles. Add denial tests for a sales leader and protected or unrelated accounts.
